# Cred Domain Support Agent

A LangGraph-orchestrated support agent for a fictional lending company, **Cred**.

The agent answers loan-policy questions using a local knowledge base and looks up loan application status from a deterministic dataset.

The project is developed in phases, with deterministic local execution prioritized before any real LLM/API integrations.

---

## Current Phase

### Phase 3 — Evaluation, Observability & FastAPI Deployment

Phase 1 and Phase 2 are frozen. Phase 3 wraps the existing support agent with an HTTP API, structured request observability, and deterministic evaluation.

Phase 3 implements:

1. FastAPI deployment
2. Pydantic request/response models
3. `/health` health endpoint
4. `/ask` agent endpoint
5. Structured JSONL request logging

9. 15-query RAG Triad evaluation

All functionality is designed to run with:


No hosted LLM API key is required for deterministic execution.

## 3. Agent Graph

The LangGraph implementation is in:

```text
agent/graph.py
```

The graph contains:

```text
guard_input
load_memory
classify_intent
rag_answer
status_lookup
format_response
persist_memory
```

High-level flow:

```text
START
  -> guard_input
  -> load_memory
  -> classify_intent
  -> rag_answer OR status_lookup
  -> format_response
  -> persist_memory
  -> END
```

Blocked inputs are routed directly to response formatting.

Intent routing is deterministic:

* Queries containing an `LA-\d{4}` record ID and status/application language → status tool
* Other queries → RAG

The frozen public invocation interface is:

```python
from agent.graph import run_query

result = run_query(
    query=user_query,
    thread_id=thread_id,
)

structured_response = result["structured_response"]
```

## 4. Status Tool & Escalation

The status tool is implemented in:

```text
agent/tools.py
```

Interface:

```python
check_loan_application_status(record_id: str)
```

It reads from the canonical `LOAN_APPLICATIONS` dataset.

### Escalation score

```text
fraud_signal = 1 if flagged_for_fraud_review else 0
recency_signal = 1 - (days_since_created / 30)

escalation_score =
    0.55 * fraud_signal +
    0.45 * recency_signal
```

The score is clamped to `[0, 1]`.

The threshold is calibrated from the actual dataset:

```text
P25(days_since_created) = 8.0
```

Therefore:

```text
P25 recency signal = 1 - (8 / 30)
                    = 0.733333...

ESCALATION_THRESHOLD
= 0.45 * 0.733333...
= 0.33
```

An application is escalated when:

```text
escalation_score >= 0.33
```

## 5. Memory & Structured Output

Memory is implemented in:

```text
agent/memory.py
```

and persisted under:

```text
transcripts/memory/
```

Memory is stored per thread as JSON containing the thread ID and user/assistant messages.

A follow-up such as:

```text
What is its current status?
```

can reuse the most recent loan application ID from the same thread.

Fresh threads start with empty history.

Structured output is defined in:

```text
agent/schema.py
```

The response contains:

```text
answer
route
escalation_score
thread_id
record_id
grounded
```

Responses are validated using Pydantic before being returned.

## 6. Guardrails

Guardrails are implemented in:

```text
agent/guardrails.py
```

### PII masking

The input guardrail masks:

```text
PAN
Grouped Aadhaar
Bank account numbers
```

using:

```text
[PAN_MASKED]
[AADHAAR_MASKED]
[BANK_ACCOUNT_MASKED]
```

The original unmasked query is not persisted.

### Prompt injection

Instruction-override attempts such as:

```text
Ignore previous instructions
Reveal your system prompt
```

are detected and blocked.

Blocked requests return:

```text
Prompt injection detected.
```

### RAG groundedness

The guardrail reuses the frozen Phase 1 `grounded` result.

No second similarity calculation or replacement threshold is introduced.

Unsupported RAG queries return:

```text
I don't know based on the Cred knowledge base.
```

## 8. Observability & JSONL Logging

Structured API request logging is implemented in:

```text
observability/logging.py
```

Logs are written to:

```text
transcripts/logs/api_requests.jsonl
```

Each API request produces exactly one JSONL record.

### Logged fields

Each record contains:

```text
trace_id
timestamp
method
path
masked_request_text
status_code
duration_ms
route
grounded
error
```

Example structure:

```json
{
  "trace_id": "uuid",
  "timestamp": "timestamp",
  "method": "POST",
  "path": "/ask",
  "masked_request_text": "How is EMI calculated?",
  "status_code": 200,
  "duration_ms": 279.14,
  "route": null,
  "grounded": null,
  "error": null
}
```

### PII-safe logging

API request text is passed through the same frozen Phase 2:

```python
agent.guardrails.mask_pii()
```

before being written to the JSONL log.

For example:

```text
Please check my PAN ABCDE1234F, Aadhaar 1234 5678 9012,
and bank account 1234567890123
```

is logged as:

```text
Please check my PAN [PAN_MASKED], Aadhaar [AADHAAR_MASKED],
and bank account [BANK_ACCOUNT_MASKED]
```

Raw PII is therefore not persisted in the request log.

## 9. RAG Triad Evaluation

Phase 3 evaluates the frozen agent using a fixed set of exactly **15 queries**.

The evaluation dataset is defined in:

```text
eval/part3_eval_dataset.py
```

The evaluation implementation is in:

```text
observability/rag_triad.py
```

### Evaluation coverage

The dataset contains:

* **15 total queries**
* **12 knowledge-base topics**
* **2 out-of-scope queries**
* **1 application-status routing edge case**

The 12 knowledge-base topics are:

```text
loan eligibility
EMI calculation
credit card fees
KYC requirements
fraud dispute resolution
account closure
interest rate slabs
prepayment penalties
minimum balance
credit score factors
joint account rules
NRI account eligibility
```

The dataset validates that exactly 15 queries are evaluated and that all required topics are covered.

### RAG strategy

The evaluator uses the frozen Phase 2 configuration:

```text
Strategy: sentence
Top-k: 3
Similarity threshold: 0.05
```

### RAG Triad metrics

Each query is evaluated on three dimensions:

#### Context Relevance

Measures whether the retrieved context contains information relevant to the query.

#### Groundedness

Measures whether the generated answer is supported by the retrieved context and the frozen groundedness signal.

#### Answer Relevance

Measures whether the generated answer directly addresses the user's query.

### Deterministic MOCK_LLM judge

The evaluator includes an evaluation-only:

```text
MockLLMJudge
```

It operates under:

```text
MOCK_LLM=true
```

The judge uses an explicit evaluation prompt covering:

```text
Context Relevance
Groundedness
Answer Relevance
```

The mock implementation is deterministic and performs no network calls or hosted LLM calls.

The production Phase 2 agent and RAG generation path are not modified for evaluation.
